# 客戶評分表「分析功能」逐項回覆與規格衝突檢查

> 版本 v0.1（2026-10-16）。左欄是客戶評分表原文（共同撰寫欄），右欄是本系統可直接填入的回覆；最後一節列出與現有規格（docs/04、17、21、23）的衝突與處置。口徑以 `backend/semantic/*.yaml`、`backend/security/*.yaml` 與編譯器實作為準。

## 1. 逐項回覆（可直接填入評分表）

| 項目 | 客戶要求 | 回覆（第一階段即提供，除非另註） |
|---|---|---|
| 事件分析 | 依事件、屬性、用戶分群做次數、人數、金額等指標交叉分析；說明是否抽樣，大量資料時能否不抽樣或自行設定抽樣比例 | 支援 14 種聚合（總次數、用戶數、人均、去重數、求和、均值、人均值、最大、最小、P25／50／75／90、MAU）、公式指標、巢狀且／或篩選（事件屬性、用戶屬性、分群、時段）、≤3 維分組與 Top N、分鐘到月粒度、對比上期。**預設不抽樣**：用戶數用精確去重（`uniqExact`），日聚合走物化視圖；使用者可自行設定抽樣比例（按用戶分桶抽樣，`SAMPLE 1/2…1/100`），結果標示抽樣與推估。已在真 ClickHouse 以 30 條黃金查詢驗證誤差 0（`backend/semantic/compiler`）。 |
| 漏斗分析 | 轉換窗口期（3／7／14／30 天）；可用業務 ID（訂單編號、購物車編號）串成同一流程；步驟可含線下事件（開戶完成、成交） | 窗口 1 分鐘到 90 天任意設定；步驟 2–10 步，每步可加屬性條件；**關聯屬性**可指定業務 ID（訂單編號、帳戶、商品代號），同一業務 ID 的事件才算同一流程；順序嚴格／寬鬆兩種；分組對比（維度或分群）、每日趨勢；流失用戶可下鑽到用戶列表並存成分群。線下事件（開戶完成、成交、入金）由數據中台批次導入成同一張事件表，與 App／Web 事件同等參與漏斗（已在端到端測試：`bond_order → bond_deal`）。 |
| 留存分析 | 依初始行為與回訪行為計算留存，可依分群比較 | 初始行為與回訪行為各自可選事件與篩選；按日／週／月、N 期、含當日、連續留存與流失模型；比例／人數／LTV 顯示；分群或維度對比。實作為 ClickHouse `retention()`，與事件表同源、不抽樣。 |
| 歸因分析 | 多觸點歸因（首次、末次、線性等），跨 Web 與 App，可設定歸因窗口期 | 五種模型：首次、末次、線性、位置權重（U 型，權重可調）、時間衰減（半衰期可調）；觸點可命名、可加篩選；窗口當天或自訂天數（例：文章瀏覽後 14 天內開戶）；目標指標總次數或金額求和。跨 Web／App 靠 OneID 歸戶（登入客戶代碼為錨，裝置／Cookie 關聯規則同神策 IDM 3.0，docs/19），不是靠同一裝置。 |
| 路徑分析 | App 內路徑與迷航分析，起訖事件可自訂（含「離開 App」為結束事件），節點可用事件而不只頁面標題或網址 | 起始或結束事件任選；節點就是事件字典裡的事件（可按屬性拆分成子節點，例：`page_view` 依 page_group），不限頁面標題／網址；「離開 App」以 `$AppEnd`（App 退到背景／關閉）與會話逾時兩種方式定義結束；步數、會話間隔、合併重複可設；桑基圖節點可展開、設為新起點、下鑽用戶列表。路徑預設抽樣 1/10（與神策相同），可調 1/1 到 1/100 並標示。 |
| 間隔與分佈分析 | 首次登入到首次下單的時間間隔；交易次數分佈 | 間隔分析：起始事件到結束事件的首次／末次間隔，分佈直方圖、中位數、P90，可分組；分佈分析：某事件在期間內的次數或數值分佈（例：交易次數分佈、單筆金額分佈），區間可自訂。第一階段以事件分析樣板的聚合實作，獨立頁面在 M4 前完成。 |
| Session、熱點圖與錄影 | 著陸頁熱點圖、點擊熱區；Session 錄影（須個資遮蔽） | **Session 分析**（會話時長、深度、跳出、入口／出口）支援。**熱點圖與錄影不在本系統範圍**：本系統承接 GA360 事件，不蒐集 DOM 快照與滑鼠軌跡，這是前端埋點工具的能力。建議由 GA360 導入商搭配前端錄影工具（如 Microsoft Clarity，免費、具輸入欄位與文字遮罩）或客戶既有工具提供；本系統可接收其 session id 作為事件屬性，從漏斗流失或路徑節點跳轉到對應錄影。 |
| 用戶分群 | 依行為與屬性建立分群（含「完成 A、未完成 B」）；定時滾動更新；匯出或回寫至 CDP／MA | 規則分群支援屬性、事件（做過／未做過、次數、求和）、行為序列、分群、函數五類條件，巢狀且／或與規則組交／聯／差，「完成 A 未完成 B」直接用差集或「未做過」條件；分析結果（漏斗某步流失、路徑節點）一鍵存成分群；手動或例行（日／週／月）更新、版本保留、回收站；匯出走審批並加浮水印；回寫以簽章 Webhook／GCS 檔案／Kafka 推送代碼化名單到 CDP／MA（新 MA 工具規格確定後加專用連接器）。 |
| 儀表板 | 業務單位自行建立並共享儀表板，具權限控管；是否需原廠或廠商另外客製 | 任何分析結果可存為看板卡片；看板由業務單位自行建立、編排、分享給角色或個人，權限沿用模組矩陣與數據權限（看的人只看到自己有權的卡片與列）。不需廠商客製；神策既有概覽依盤點清單由我們重建一次作為起始看板。 |
| 取數 API、SQL 與 AI 介接 | 查詢 API 或 SQL 介面，無筆數上限；是否支援 MCP 或 AI Agent 介接 | 查詢 API（`/v1/analytics/*`、`/v1/semantic/compile`、分頁取數）與自定義 SQL（唯讀 SELECT／WITH，依權限的表目錄，1,000 列線上預覽）皆提供；大量取數走**非同步匯出任務**：分頁或檔案（GCS／SFTP），**沒有硬性筆數上限**，但依金融業內控要求經審批、加浮水印、寫審計，單次上限由系統管理員設定（預設 10 萬列，可放寬）。AI 介接：所有能力以 **MCP 工具**（29 個工具，`backend/mcp/tools.yaml`）暴露，含權限、預算、脫敏與審計閘道，任何 MCP client（含客戶自有 Agent）可接；本系統內建的 AI 洞察 agent 依客戶決定列第二階段。 |

## 2. 與現有規格的衝突與處置

| # | 衝突 | 處置 |
|---|---|---|
| 1 | docs/04 §1.3 寫「`uniq_users` 預設 `uniqCombined64`（近似）」，編譯器實作與黃金測試是精確去重（`uniqExact`）、用戶數不走 MV | 以編譯器為準：**預設精確、不抽樣**（評分表要求「大量資料能否不抽樣」）；近似只在使用者打開「快速估算」時用。docs/04 已修。 |
| 2 | docs/04 把留存、間隔、分佈、Session 列 P1、熱圖 P2；評分表把它們列在同一張功能表 | 留存已在 docs/23 必留；間隔、分佈、Session 升為第一階段「簡化版」（以事件分析樣板的聚合實作，M4 前）；熱圖／錄影明確回覆不在範圍並給替代（見上表）。docs/23 §1 已補。 |
| 3 | 評分表要求「離開 App」可作路徑結束事件；事件字典有 `$AppEnd` 但路徑規格未定義「離開」節點 | 路徑樣板加入虛擬結束節點「離開 App」= `$AppEnd` 或會話逾時；docs/17 §5.8 補一句。 |
| 4 | 評分表「無筆數上限」vs docs/21 自定義 SQL 1,000 列預覽、masking.yaml 匯出上限 10 萬列 | 不改內控：線上預覽 1,000 列、匯出經審批；「無上限」以非同步匯出任務與分頁 API 達成，上限改為系統管理員可設（預設 10 萬）。docs/21 補註。 |
| 5 | 評分表「回寫至 CDP／MA」vs 客戶說 MA／LINE 不列入本案 | 回寫介面（Webhook／GCS／Kafka）第一階段就有；MA 專用連接器等規格。回覆已如此寫。 |
| 6 | 評分表「業務單位自行建立並共享儀表板」vs docs/17 只有「總覽依盤點重建」與「存為看板卡片」 | 規格要補：看板建立／編排／分享／權限（第一階段基本版：卡片 = 已存報表，分享給角色或個人）。列入 docs/17 §5.1 修訂與 M4 工作。 |
| 7 | 評分表「MCP／AI Agent 介接」vs docs/23 AI 全部延後 | 區分「AI 介接」與「內建 agent」：MCP 工具閘道（權限／預算／脫敏／審計）第一階段保留並可對外提供，內建洞察 agent 第二階段。docs/23 §1 AI 列改寫。 |
| 8 | 漏斗「業務 ID 串流程」：docs/04 §2.2 寫 `sequenceMatch + arrayJoin` 版本，尚無實作 | 本次實作：關聯屬性作為 `windowFunnel` 的分組鍵（`GROUP BY one_id, 關聯值`），不需 UDF；黃金測試含訂單編號串接案例。 |
