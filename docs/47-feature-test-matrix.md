# 47. 功能點 × 測試對照表（分析模組）

> 2026-10-29 建立。起因：Windy 在示範站選「按月」仍顯示按天，並指出「畫面有欄位但不一定能用」。查證後確認：真後端算得對，但原本的自動測試只有 **後端黃金測試**（編譯器結果對獨立 oracle）和 **一條瀏覽器主線**，畫面上的每個選項沒有逐一自動點過；示範站更是固定資料。
> 本表把 docs/04（含 §0b 對照舊平台使用指南的補齊清單）的功能點逐條對到測試，**沒有測試的就標未驗證，不算完成**。

## 怎麼看

| 標記 | 意思 | 代表的測試 |
|---|---|---|
| ✅ 端到端 | 畫面逐項操作 → 真後端（ClickHouse＋黃金資料）→ 斷言條件有送出、結果照選項變化 | `web/tests/e2e/controls*.spec.ts`（#97、#98）、`mainline.spec.ts` |
| 🟢 後端 | 查詢編譯結果與獨立 oracle 逐值一致（誤差 0），但畫面沒有逐項自動點 | `backend/semantic/compiler/golden.py` 案例編號（Q／F／R／P／A／U） |
| ⚪ 未驗證 | 只有前端單元測試或完全沒有自動測試 | — |
| ❌ 未實作 | 規格（docs/04、§0b）有，程式沒有 | — |

✅ 的範圍：代表「該選項送得出去、後端接受、關鍵不變式成立」（例：時間桶對齊、各組加總 = 合計、嚴格 ≤ 寬鬆），**不等於**每個選項的數值與圖表都全面驗收；數值正確性由 🟢 黃金測試負責，圖表呈現目前多數仍是 ⚪ 未驗證（Codex 審查 #98 2026-10-30）。

規則（之後每個 PR）：
1. 畫面新增或修改選項 → 同一個 PR 要在 `controls*.spec.ts` 補上；選項清單從畫面讀，後端不接受就紅燈。
2. 新增查詢能力 → 黃金測試補案例。
3. 功能「完成」= 本表該列是 ✅；只有 🟢 的對外只能說「後端已驗證，畫面未逐項驗證」。
