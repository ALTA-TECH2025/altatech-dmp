# 定案紀錄（Decision Log）

> 目的：同一天有多條工作線（人、Codex、Claude 各自開 PR）時，決策容易前後衝突。**動手改文件、契約或程式前，先查這張表；做出新決定時，先在這裡加一列，再開 PR。** 一個決策一列；被推翻的決策不刪，狀態改「已推翻」並指向新的那一列。
>
> 欄位：編號｜日期｜決策｜誰定的｜影響的文件與 PR｜狀態（有效／已推翻／待確認）。「待確認」= 要等永豐、偉康、法務或運維回覆，**在回覆前不要改文件去預設答案**。

## 4. 怎麼用這張表

- 開 PR 前：PR 描述的「關聯 Issue」欄引用決策編號（例：`依 D-10、D-14`）；沒有對應編號的新決定，先在這裡加一列。
- 兩條工作線同時改同一主題時，以這裡的編號與日期為準，晚的推翻早的，並在 §2 留紀錄。
- 「待確認」有回覆後，移到 §1 成為決策，並更新引用它的文件。
