# 分群、標籤與自定義 SQL（v1.0，2026-10-15）— 對齊舊平台「分群」「標籤管理」「自定義 SQL」

> 依舊平台文件 segment_management、tag_management、custom_query（v3.0）逐項對照；原型「營運 › 分群與標籤」「分析 › 自定義 SQL」；契約 `backend/openapi.yaml` 的 Segments／SQL 標籤。角色對應本系統五種角色（docs/10 v0.4）。

### 1.1 行為序列與導入名單（2026-10-18）

- **行為序列**＝「完成 A 後 N 天內做 B」：ClickHouse `windowFunnel` 預設模式（從第一步起算，後續每步都要在窗口內；中間可夾其他事件；同一秒的先後以寫入順序為準）。「沒有依序完成」= 全體 − 依序完成者（行級範圍照套）。
- **導入名單**分兩步：
  1. `POST /v1/segments/imports`：收客戶代碼或 one_id（≤ 200,000 筆）。客戶代碼在 API 記憶體裡以 `token_v1(k_idm)` 轉成 one_id（與舊平台登入 ID、GA user_id 同一把金鑰），**原始代碼不寫入 ClickHouse、store 或審計**；只存 one_id 於 `dmp.segment_imports`。回總數、去重後、對到用戶表、沒對到、格式錯誤。
  2. 以 `kind=import` 建分群（`rule.source = {type: import, import_id}`）：固定名單、強制手動、不可改規則；計算時一樣與資料權限交集。換名單＝重新導入、另建分群。
- 金鑰沒注入（`DMP_K_IDM`）或沒接 ClickHouse 時回 503，不會用明文代碼。
- 標籤也有 `kind=import`（`dmp.tag_imports`，一人一值），目前給舊平台標籤快照用（docs/22 §3.4）。

分析頁引用分群：篩選與分組可選「最新結果」「動態匹配（事件日期 = basetime）」「自定義版本」；注意 T+1 計算的 basetime 比行為日期晚一天。

## 3. 自定義 SQL

| 舊平台功能 | 本系統 |
|---|---|
| 前提：自定義 SQL 功能權限 + 數據表數據權限；事件表／用戶表行權限、列權限、脫敏 | 數據分析、資訊管理、系統管理員；數據表權限由資訊管理在「數據表管理」分發 |
| 數據庫表目錄（表、欄位、型別；插入表名／查詢語句）；函數目錄；元事件輔助 | 相同（events、users、user_tags、segment_members、dim_*、id_map（限資訊管理）、中間表） |
| 編輯區：格式化、解釋、清空、動態參數；最多 5 條同時運行 | 相同；EXPLAIN 顯示分區裁剪、掃描估算、遮罩與行級規則 |
| 結果：預覽 1000 列（大量取數走非同步匯出任務：經審批、浮水印、審計，上限由系統管理員設定，預設 10 萬列，docs/26 衝突 4）；Excel／CSV 下載；複製前 100 列；可視化（表格、折線、柱狀、堆疊柱、柱線、環圖；X／Y≤5／分組≤5／排序／分組值前 10–50） | 相同；下載走匯出審批與浮水印 |
| 查詢記錄：30 天內最近 100 條；插入編輯器；成功者可下載 | 相同 |
| 已存查詢目錄（分組）；保存至概覽／書籤；動參在概覽可改、日期型可綁全局日期 | 相同 |
| 保存到中間表（SQL 任務 → 任務管理 + 數據表管理）；添加到業務集市 | 相同（中間表可被標籤與分析引用） |
| 跨專案查詢（平台帳號） | 保留：證券示範專案為單一專案 |
| 脫敏預校驗：SQL 涉及脫敏欄位直接報錯 | 相同；`*`／`alias.*` 先依 schema 展開成明確欄位再檢查，展不開的 `*` 與 `COLUMNS()` 拒絕；CTE 只在自己 scope 且不帶資料庫限定時才算 CTE（`dmp.<同名>` 一律當實體表授權）；另限制唯讀（SELECT／WITH），DDL／DML 拒絕 |

執行引擎：Trino 做權限與遮罩改寫後下推 ClickHouse；資源群組 `dmp`（掃描 2 TB／查詢、逾時 300 s、每人 5 併發）；審計 `query.sql`、`export`。
