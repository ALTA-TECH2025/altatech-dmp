# 48. 原始匯入檔的存放、保留與刪除（維運規範草稿，#54）

- 狀態：**草稿，待客戶確認**。標「客戶決定」的欄位沒有填預設值，確認後回寫本檔與 #54。
- 對象：客戶 IT、資安、法遵；DMP 研發與運維。
- 這是個資處置原則文件的第 4 項；相關文件為 docs/22 §3（導出與載入）、docs/42 §7（校驗與原檔的關係）。

## 0. 一句話

原始匯入檔含個資，DMP 只讀取、清洗，不修改。原檔放在哪、保留多久、什麼時候由誰刪、刪了怎麼留紀錄，照本規範處理。**原檔要等該分片的遷移資料校驗簽結（docs/42）後才能刪**，因為 key 核對與個資反查都要用到原檔。

## 1. 有哪些檔案

| # | 檔案 | 誰產生 | 含個資 | 目前位置 | 目前保留 |
|---|---|---|---|---|---|
| F1 | 客戶原始匯入檔：舊平台每日格式檔（約 3.8 GB／日）、數據中台匯出檔、HDFS 導出的 Parquet | 客戶／舊平台 | **是** | 客戶端（待定） | 無規範 |
| F2 | 傳輸中間副本：distcp 暫存、SFTP 落地區、搬檔用的磁碟或 bucket | 客戶或傳輸流程 | **是** | 待定 | 無規範 |
| F3 | DMP 從舊平台查詢 API 導出的檔 `sa_<資料集>_<日期>.jsonl` | **DMP**（遷移頁「導出任務」） | **是**：登入 ID 原值、L4 屬性尚未剔除 | `DMP_MIGRATION_WORK`，未設定時是 `/tmp/dmp-migration` | **不會自動刪除**（見 §4 缺口） |
| F4 | DMP 清洗後的暫存檔 `*.staged.jsonl` | DMP | 否：登入 ID 已代碼化，L4 與個資樣式已剔除 | ClickHouse `user_files` 目錄（正式環境改物件儲存） | 不會自動刪除 |
| F5 | DMP 隔離檔 `*.quarantine.jsonl` | DMP | 否：只記行號與原因，不記原文 | 同 F4 | 不會自動刪除 |
| F6 | `dmp.raw_legacy` 表 | DMP | 否（內容同 F4） | ClickHouse | 依載入時間 7 天 TTL |

F1、F2、F3 都含個資，全部適用 §2 的規範。F3 雖由 DMP 產生，但內容等同原檔，不能當成 DMP 的一般暫存檔。F4–F6 已去個資，另訂較寬鬆的保留期即可（§2.6）。

## 2. 規範條目

### 2.1 存放位置與權限

| 項目 | 建議 | 客戶決定 |
|---|---|---|
| 位置 | 客戶內網的專用目錄或專用 bucket；不放在 DMP 應用主機的系統暫存目錄（`/tmp`） | 位置：＿＿＿＿ |
| 加密 | 靜態加密（磁碟或 bucket 層級）；傳輸一律走加密通道（SFTP／HTTPS） | 加密方式：＿＿＿＿ |
| 權限 | 最小權限：只有遷移作業的服務帳號可讀；DMP 服務帳號只讀不寫、不刪（啟用 §2.4 時另給刪除權限）；人員讀取需申請 | 可讀名單：＿＿＿＿ |
| 存取紀錄 | 讀取、複製、刪除都留存取日誌，至少保留到簽結後＿＿年 | 日誌保留：＿＿＿＿ |
| 網路 | 原檔不出客戶內網；DMP 研發不在內網外取得原檔（docs/42 §1） | — |

### 2.2 保留期限

- **簽結前不得刪除**。簽結 = 該分片（日 × 資料集）的遷移資料校驗全部通過，並由客戶簽核（docs/42 §5）。
- 建議期限：**簽結後 N 天刪除**。N 給「發現問題要重載」留緩衝。
- 校驗不通過、或客戶要求重載的分片，原檔保留到重載後再次簽結。
- 遷移全部完成（並行期結束）後，仍未刪除的原檔一律在＿＿天內清空。

| 項目 | 客戶決定 |
|---|---|
| N（簽結後保留天數） | ＿＿天 |
| 並行期結束後的清空期限 | ＿＿天 |
| 法規或內規是否要求最短保留 | 是／否；依據：＿＿＿＿ |

### 2.3 刪除方式與紀錄

- 誰刪：＿＿＿＿（建議由客戶 IT 執行，或客戶授權 DMP 自動刪除，見 §2.4）。
- 怎麼刪：
  - 物件儲存：刪除物件，**連同歷史版本與回收區一起清**；有物件鎖定（WORM）的 bucket 要先確認鎖定期。
  - 檔案系統：刪除檔案；若磁碟是專用卷，遷移結束後整卷銷毀或重新加密（雲端磁碟與 SSD 上逐檔覆寫不保證有效，不以覆寫當主要手段）。
- 刪除紀錄：每個檔案一筆，存放在客戶的稽核系統或 DMP 稽核日誌（啟用 §2.4 時）。

| 欄位 | 說明 |
|---|---|
| 檔名與路徑 | 刪除前的完整位置 |
| SHA-256 | 收檔登記時算的雜湊（§3 第 1 步），刪除時重算比對 |
| 分片 | 日期 × 資料集 |
| 簽結編號與日期 | 對應的遷移資料校驗單 |
| 刪除時間 | 含時區 |
| 執行者 | 人員帳號或服務帳號 |
| 刪除方式 | 物件刪除＋版本清除／整卷銷毀等 |
| 副本處理 | 該檔的 F2 中間副本是否一併刪除 |

### 2.4 選配：DMP 自動刪除

- 內容：DMP 在「分片已簽結」且「過了 N 天」後，自動刪除 F1／F3 或把它搬離暫存區，每次刪除寫入 DMP 稽核日誌（欄位同 §2.3）。
- 是否啟用：**客戶決定**（啟用／不啟用）。
- 啟用時需要：
  - 客戶給 DMP 服務帳號該位置的刪除權限。
  - DMP 另開 contract PR 定義部署設定與稽核事件。
  - 預估 1–2 人日。
- 不啟用時：DMP 只提供「可刪清單」（已簽結且超過 N 天的分片與檔案 SHA-256），由客戶 IT 依清單執行並回填刪除紀錄。

### 2.5 中間副本與備份

- F2 中間副本、F3 DMP 導出檔，與原檔同一規範：同樣簽結後 N 天、同樣留刪除紀錄。
- 備份：原檔若被納入客戶例行備份，備份媒體的保留期要＿＿（建議不備份原檔，因為原檔可從舊平台重新導出，直到舊平台下線）。
- 舊平台下線後，原檔就是唯一來源；下線前要確認所有分片都已簽結。

### 2.6 DMP 去個資暫存（F4–F6）

- F4 暫存檔與 F5 隔離檔已不含個資，但仍是遷移中間產物。建議與原檔同時刪，或保留到並行期結束；保留期由客戶決定：＿＿。
- F6 `dmp.raw_legacy` 維持 7 天 TTL；校驗工具需在 7 天內跑完該分片，否則要重新載入。

## 3. 一個分片的流程

1. **收檔登記**：原檔到位後記檔名、大小、SHA-256、來源、收檔時間。
2. **清洗載入**：DMP 讀原檔，產出 F4／F5，載入 ClickHouse；DMP 不改原檔。
3. **校驗**：依 docs/42 六層校驗；L2（key 公式）與 L5（個資反查）在內網讀原檔。
4. **簽結**：客戶簽核該分片的校驗報告，記簽結編號與日期。
5. **保留 N 天**。
6. **刪除**：照 §2.3 刪除 F1、F2、F3，並回填刪除紀錄；未啟用 §2.4 時由客戶 IT 依 DMP 給的可刪清單執行。
7. **抽查**：每月抽查刪除紀錄與實際位置一致（找不到應已刪除的檔）。

## 4. DMP 端現況與缺口

- **F3 預設落在 `/tmp/dmp-migration`，且導出後不刪**。這是 DMP 自己產生的含個資檔案，目前不在任何規範內。建議另開功能 PR 處理：
  - 未設定 `DMP_MIGRATION_WORK` 時拒絕執行導出，不再退回 `/tmp`；部署文件與 helm values 明確指定受控目錄。
  - 清洗完成後在工作目錄登記 F3 的 SHA-256，讓它和原檔一樣受 §2.2–§2.3 管理；啟用 §2.4 時一併自動刪除。
- F4／F5 目前也不會自動刪除，等 §2.6 保留期確認後，再跟著同一個功能 PR 加清理。
- 本規範確認前，正式環境不執行 F3 導出；需要先行測試時，只用合成資料。
