## 1. 第一階段交付什麼

一條可以驗收的路，全部用合成資料與模型替身（`provider: test-double`）跑通：

1. 使用者在工作台選技能（只列已發布版本，1029-2）。
2. 問數：「上週開戶漏斗跟前週比」。上週＝上一個完整的週一到週日（1029-7）。
3. 口徑不明時補問：「開戶」對到 `kh_apply` 或 `kh_review_pass` 未定 → run 進 `waiting_input`，給選項；等待不限時、不佔同時名額（1029-5、1029-12）。
4. 看步驟進度；可取消、失敗可重試。
5. 看結果與證據：畫面數字由 DMP 依使用者本人權限直接給（D3）；每個結論數字能點回證據（A20）；口徑未經客戶核定的結果標「口徑待確認」（1029-9）。
6. 一鍵建「開戶主管週報」私人看板草稿：3–4 張卡，存 `kind + query`（B01）；之後使用者可自行編輯。
7. 模型未設定時走規則模式：畫面標「規則模式（非 AI）」，只給候選、使用者確認後才查、不產生診斷文字（1029-1、A27）。

**不在第一階段**：S6 受眾草稿（P2）、定期重跑與權限失效暫停（P2 之後）、正式模型與 Gateway 接入（等 #95 評估）、分享／排程／送審（D4：人在畫面上操作的既有流程不變）。

## 3. 先補的契約（一個 contract PR，實作前）

以下是研發提案、屬新設計的項目（待確認表 Q16、Q27–Q30、Q33–Q35）。C1–C7 已由 Windy 2026-10-31 確認，契約見 PR #117；C8 是程式改動，放在後端 PR。

| 編號 | 內容 | 提案 | 對應 |
|---|---|---|---|
| C1 版本快照 | run 固定引用哪些版本 | `AgentRun` 記：技能 `{name, version, content_digest}`、引用書籤 `{bm_id: query_digest}`（run 開始時快照書籤 query，整個 run 用快照）、`contracts`（現有）。書籤之後被改不影響舊 run，重看結果時標「書籤已變更」 | Q29、Q34 |
| C2 參數覆寫 | 使用者能改哪些參數 | `AgentRunCreate` 加 `params`：只接受該技能版本宣告為 `user_overridable` 的鍵，其他鍵回 400 `INVALID_ARGUMENT`（目錄已有）；覆寫值記在 run 上 | Q29 |
| C3 專案來源 | run 在哪個專案執行 | 沿用分析 API 的專案設定，不讓請求或模型指定；`drop_identity_args` 加 `project`（A14） | Q33 |
| C4 寫入冪等 | 建看板草稿只建一次 | 唯一冪等來源 = `agent_operations`（#62 已實作）：Gateway 先呼叫看板服務層驗證與組裝，再與 operation 紀錄同一交易寫入；同 `operation_id` 不同 `args_digest` 回 409 `CONFLICT`（B03、B04） | Q27 |
| C5 建 run 的冪等鍵 | 同鍵不同內容 | 回 409 `CONFLICT`（與看板端點一致）；鍵保留 24 小時（已確認） | Q16 |
| C6 可見性 | 誰看得到 run 與 AI 看板 | run：只有發起人看得到。系統管理員看別人的 run 能看到什麼仍待法遵（Q13），第一階段先不開放。AI 建的看板：擁有者私人、不分享，加 `origin: {run_id, skill}` 讓畫面標「AI 草稿」；擁有者可照一般看板編輯 | Q13（部分） |
| C7 讀取查詢 ID | 逾時重試與中止查詢 | ClickHouse `query_id` = `run_id:step_id:attempt`；`operation_id` 只給寫入 | Q28 |
| C8 語意層版本 | `contract_versions()` 回哪些鍵 | 先維持整檔版本（semantic／tools／oneid_rules，加 `preset_properties`），單一物件版本留到之後 | Q35 |

看板版本欄位（Q30）只有定期重跑更新同一份看板時才需要，第二階段之後再定。
