# AI Gateway 整合設計：模型、積分與資料權限用同一個身分打通

- 狀態：草案（規格先行，未實作）。對應 Issue #34、RFC #36（docs/41 決定 1029-6、1029-13、1029-14）。
- 起因：Windy 2026-10-29 提供 data-di AI Gateway 的畫面（概覽、KEY 管理、模型版本、積分定價、MODERATION、ANONYMIZATION、用量通知），並說明：
  - Gateway 可以地端部署，但目前是給另一套 agent 產品用。
  - 程式碼在其他 repo，**2026-10-30 向其他研發確認**能不能複用。
  - 目標是把「資料權限」、「角色積分」、「資料取用權限」打通。
- 本文先定 DMP 這一側的設計，不管最後是複用現有 Gateway 還是在本案重寫，下面的身分、帳本、權限規則都一樣；實作路線在 §7 二選一，等研發確認後再定。
- 問不到答案的項目列在 §9「待確認」，不填預設值。

## 1. 要解決的問題

AI 工作台每一次分析都會碰到兩種資源：

| 資源 | 問題 | 現在誰管 |
|---|---|---|
| 資料 | 這個人能看哪些資料、哪些欄位要遮、人數太少要抑制 | DMP Tool Gateway（`backend/mcp/tools.yaml`）＋查詢編譯器（`compiler/policy.py`），每步 `authorize()` |
| 模型 | 這個人能用哪個模型、用了多少積分、送出去的內容安不安全 | 還沒有。`backend/insight_agent/model.py` 的 `ApiDriver` 沒接任何供應商 |

如果模型另外走一個不認得 DMP 使用者的 Gateway，會出現三個斷點：

1. **積分算不到人**：Gateway 只看得到 KEY，看不到是 DMP 的哪個人、哪個角色在用，1029-6「依角色、依週期設積分上限」做不到。
2. **資料等級管不到模型**：Gateway 不知道這次送出去的內容含不含個資，也不知道這個模型可不可以收。（Windy 2026-10-29：由模型接入時的內規控管，見 §5。）
3. **稽核串不起來**：同一次分析，資料查詢記在 DMP、模型呼叫記在 Gateway，用 `request_id` 對不起來。

## 2. 核心設計：兩道閘、一個身分、一本帳

```
使用者（session / 排程擁有者）
   │  Subject = {user_id, roles, project, 權限指紋}
   ▼
run 控制器（journal：run_id、step_id）
   ├─► 資料閘 Tool Gateway（既有）──► 編譯器（列級／欄位遮罩、K 匿名）──► ClickHouse
   │        回 data（給畫面）＋ model_view（給模型，只有彙總投影）
   │
   └─► 模型閘 AI Gateway（本文）
            1 身分與權限：這個角色能不能用這個模型版本
            2 配額：角色＋週期的積分上限、環境總上限（呼叫前預扣）
            3 內容檢查：內容審查（MODERATION）→ 匿名化（ANONYMIZATION）
            4 路由：選 KEY（狀態、RPM／TPM、備援順序）→ 依 Protocol 送出
            5 結算：依模型版本定價算積分 → 寫用量帳本（帶 run_id、step_id、request_id）
```

- **一個身分**：兩道閘都用 run 綁定的 Subject，來源只有 session（互動）或擁有者現在的角色（排程），與 docs/39 §5 相同。模型輸出的身分參數一律丟棄（`drop_identity_args`）。
- **一套權限**：都讀 `backend/security/rbac.yaml`。模型能用哪些版本、積分上限，在角色設定裡配置（1029-6、1029-3 同一個頁面），不在 Gateway 另開一套帳號。
- **一本帳**：每次模型呼叫寫一筆用量紀錄，帶 `run_id`、`step_id`、`request_id`（與 X-Request-Id 同一個，docs/46）；資料查詢的審計也帶同一組編號。

## 3. 身分傳遞

| 路線 | DMP 怎麼把身分交給 Gateway | Gateway 怎麼確認不是偽造 |
|---|---|---|
| 內建（§7 路線 B） | 同一個程序內呼叫，直接傳 Subject 物件 | 不需要；Subject 只能由 run 控制器建立 |
| 獨立服務（§7 路線 A） | 每次呼叫帶簽章標頭：`user_id`、`roles` 指紋、`project`、`run_id`、`step_id`、`request_id`、`purpose`、時間戳 | 用環境金鑰簽章（金鑰只放 secret_ref），Gateway 驗簽、檢查時間窗；KEY 只代表「DMP 這個環境」，不代表個人 |

- `purpose` 分 `workbench`（AI 工作台）、`moderation`、`anonymization`、`embedding` 等，讓帳本分得出積分花在哪裡。
- 排程 run 以擁有者身分記帳（同 docs/39 §5），不記在服務身分 `svc_insight` 上。

## 4. 積分與配額

### 4.1 定價（照 Gateway 現有畫面）

每個模型版本一組定價：

- 計價方式：收費／免費／限時免費（限時免費要有到期時間，到期後自動回到收費）。
- 單位：積分／1000 tokens；Input、Output 分開。
- 分段定價：輸入超過門檻（例：272,000 tokens）時，**整個請求**改用長上下文價；某格留空就回落基礎價。
- 快取命中價：開啟時，快取命中的 input tokens 用另一個價。
- **不做成本支出、業務應收、利潤率**（Windy 2026-10-29，G-Q8）：DMP 只管用量與積分；成本價欄位不進 DMP 的資料模型與畫面。

一次呼叫的積分 = 依上述規則算出的 input 積分 ＋ output 積分（含快取、分段）。進位方式待確認 G-Q4。

### 4.2 配額

| 層級 | 設定位置 | 內容 | 到達時 |
|---|---|---|---|
| 角色 × 週期 | 權限 › 角色設定（1029-6） | 每個角色可設日／週／月積分上限；未開啟 = 不限 | 該使用者的新呼叫被擋，畫面顯示用量與重置時間 |
| 環境總上限 | 模型配置頁（1029-13） | 管理員選擇開啟與數值 | 全環境暫停 AI；Email 通知收件清單（可設定），同一週期只寄一次 |
| 安全上限 | `tools.yaml` `gateway.budgets`（現行契約） | 單 run 50,000 tokens、單次查詢 20 GB、單 run 100 GB | 照現行規則，不受配額開關影響 |

- **檢查時點**：呼叫前依「已知 input tokens ＋ `max_tokens` × output 價」**預扣**，回來後依實際用量結算、退回差額。這樣兩個請求同時進來時，不會都以為還有額度。
- **併發寫入**：預扣用資料庫條件更新（`used + hold <= cap` 才成功），與 #94 書籤唯一限制同一個原則：在寫入當下擋，不靠先查再寫。
- **多角色取最大**（Windy 2026-10-29，G-Q2）：一個人同時有兩個角色時，取各角色上限中最大的一個；其中任一角色「未開啟」（不限）就視為不限。週期不同時各週期分別取最大。
- **同時執行數**：「每人同時 2 個」（`max_concurrent_runs_per_user`）只算排隊中與執行中（1029-12）；要不要改成在模型配置頁可調整，待確認（docs/41 尚未回覆）。

### 4.3 帳本

`ai_usage`（PostgreSQL，與控制面同一個 schema）每次模型呼叫一筆：

- 誰：`user_id`、角色指紋、`project`
- 哪次分析：`run_id`、`step_id`、`request_id`、`purpose`
- 用了什麼：模型版本 ID、KEY ID（不存金鑰）、Protocol
- 用了多少：input／output／快取 tokens、是否觸發分段價、積分、成本（若啟用）
- 結果：狀態、延遲、錯誤碼（照 `errors.yaml`）

概覽頁（總請求數、Token 消耗、積分消耗、錯誤率、P95 延遲、依品牌分佈）都從這本帳彙總。保存期限與刪除方式跟 Q14 一起定。

## 5. 資料權限怎麼管到模型

這是「打通」的關鍵：模型閘要知道送出去的東西是什麼等級。

1. **模型只拿得到 model_view**：資料閘已經保證模型看不到 `data`、SQL、身分，只看到彙總投影（K 匿名、依檢視者遮罩，docs/41 D3）。這條不變。
2. **模型接入依內規控管**（Windy 2026-10-29，G-Q6）：模型在「模型配置」接入前依內規審核，**不可碰個資的模型不接入模型 API**；接得到的模型都是內規允許的。DMP 端不另做逐次的資料等級比對，但模型仍只拿得到 model_view（上一點），問題文字仍先遮罩（下一點）。
3. **使用者問題文字**：先過內容審查（MODERATION，1029-1），再過匿名化（ANONYMIZATION）遮掉身分證號、手機、帳號等，才送給主模型（Q12）。匿名化規則要與 `backend/security/*.yaml` 的欄位分級一致。
4. **角色能用的模型版本**：在角色設定裡選「可用的模型版本」，沒選到的版本這個角色叫不到；AI 工作台只列出同時開啟 Tool 能力與 JSON Schema 的版本（1029-14）。

## 6. 模型版本與 KEY

照 Gateway 現有畫面的資料結構：

- **模型版本**：類型（LLM、EMBEDDING、RERANK、ASR、TTS、PDF_EXTRACTION、MODERATION、ANONYMIZATION）、支援的 Protocol、預設 Protocol 與 Model Name、Tokens 上限、最大回應 Tokens、能力開關（Tool、推理、JSON Object／Schema、圖片／文檔辨識…）、定價、內規審核狀態（未核准不可啟用）。
- **KEY**：服務商、Protocol、綁定的模型版本與部署名、RPM／TPM 上限、狀態（已驗證、待驗證、限流、異常、自動停用、已停用）、備援順序。
  - **金鑰只存 secret_ref**，畫面只顯示遮罩後的前後幾碼，日誌與錯誤訊息不得出現金鑰。
- **路由**：同一模型版本有多把 KEY 時，依狀態與負載挑選；失敗依 `errors.yaml` 判斷能不能換 KEY 重試（`retryable`）。

第一期要支援哪些 Protocol（OpenAI 相容、OpenAI Responses、Anthropic Messages、Google Gemini…），待確認 G-Q7。新增第三方 SDK 要附授權與 CVE 檢查（CLAUDE.md），能用標準 HTTP 呼叫就不引入 SDK。

## 7. 實作路線（2026-10-30 研發確認後二選一）

| | 路線 A：複用現有 Gateway | 路線 B：在 DMP 內建精簡版 |
|---|---|---|
| 做法 | 把現有 Gateway 地端部署成獨立服務（或把程式碼搬進本 repo），DMP 用 §3 的簽章標頭呼叫 | 在 `backend/` 新增模型閘模組，只做 DMP 需要的功能 |
| 好處 | 模型、KEY、定價、概覽頁都現成 | 身分、權限、帳本天生同一套；不多一個服務要維運 |
| 要先確認 | 授權與所有權；技術棧與映像（第三方套件白名單、CVE）；能不能接受 DMP 帶來的身分並依使用者／角色計額（Q44）；金鑰能不能改用 secret_ref；能不能把用量逐筆回報給 DMP 帳本；能不能進 3 台 VM＋Docker Compose（docs/45 D-01） | 工作量：模型版本、KEY、定價、配額、帳本、2–3 種 Protocol、設定頁 |
| 不做的 | DMP 不呈現 Gateway 既有的成本、應收、利潤功能（G-Q8） | 成本、應收、利潤率（G-Q8：不做） |

兩條路線在 DMP 這一側的介面相同：`ModelDriver` 改由 `GatewayDriver` 實作，呼叫時帶 Subject 與 `purpose`，拿回 `ModelTurn` 與用量。控制器、Tool Gateway、skill 都不用改。

## 8. 驗收（開工前先寫成測試）

沿用各工作流既有自測（`python3 -m … selftest`、vitest、Playwright），不另立框架；只用合成資料。

| ID | 情境 | 預期 |
|---|---|---|
| G01 | 模型在工具參數或輸出裡夾帶 `user_id`／`roles`／`project` | 丟棄並記 warning；帳本記的是 run 綁定的發起人 |
| G02 | 路線 A：簽章錯誤、過期、改過 `roles` 的標頭 | Gateway 拒絕，不呼叫模型、不扣積分 |
| G03 | 定價計算：基礎價、分段價（門檻前後各一）、快取命中、免費、限時免費到期前後 | 積分 = 預先手算的期望值（期望值寫在案例裡，不由被測程式推導） |
| G04 | 角色日上限剩 10 積分，兩個請求同時進來，各需 8 | 只有一個成功；另一個被擋；帳本合計不超過上限 |
| G05 | 預扣 100、實際用 30 | 結算後退回 70；週期用量 = 30 |
| G06 | 環境總上限到達 | 新呼叫全部被擋；收件清單收到 1 封 Email（同週期重複到達不重寄）；管理員調高上限後恢復 |
| G07 | 配額未開啟 | 不檢查；安全上限仍生效 |
| G08 | 模型版本的內規審核狀態不是「核准」 | 不能啟用、不出現在任何角色可選的模型清單；直接呼叫被擋 |
| G09 | 問題含身分證號、手機 | 內容審查通過後，送給主模型的文字已遮罩；帳本與日誌不留原文 |
| G10 | 內容審查擋下 | 不呼叫主模型；畫面顯示原因（Q37） |
| G11 | 角色沒被授權某模型版本 | 呼叫被擋；工作台的模型清單不出現該版本 |
| G12 | 主要 KEY 限流或異常 | 依備援順序換 KEY；全部失敗回目錄代碼、retryable 照目錄 |
| G13 | 金鑰外洩檢查 | 回應、日誌、帳本、錯誤訊息都不含金鑰原文 |
| G14 | 帳本與審計串接 | 同一次分析的模型呼叫與資料查詢，用 `run_id`／`request_id` 查得到同一組 |
| G15 | 排程 run | 積分記在擁有者身上；擁有者失去權限 → 排程暫停（docs/30） |

## 10. 拆 PR（各 < 400 行，契約先行）

1. **docs**：本規格（本 PR）。
2. **contract**：`rbac.yaml`（角色的積分上限、可用模型版本）；openapi（模型版本、KEY、定價、配額、帳本查詢、環境上限、通知清單）；`errors.yaml`（新增積分不足代碼，G-Q3 已決定）；`tools.yaml`（`per_user_daily_scan_bytes`／`per_agent_daily_scan_bytes` 改由配額取代）。
3. **後端 1**：模型版本、KEY（secret_ref）、定價計算與帳本；G03、G05、G13。
4. **後端 2**：配額預扣與結算、環境總上限與 Email；G04、G06、G07。
5. **後端 3**：內容審查、匿名化、模型內規審核狀態；G08–G10。
6. **後端 4**：`GatewayDriver` 接上 run 控制器、KEY 路由與備援；G01、G11、G12、G14、G15。路線 A 時改為「簽章標頭＋用量回報」，加 G02。
7. **前端 1**：模型配置頁（模型版本、KEY、定價、環境上限、通知清單）。
8. **前端 2**：角色設定加積分上限與可用模型；概覽頁（用量、積分、錯誤率、延遲）。

路線 A 時，3–5 大部分由現有 Gateway 提供，DMP 只做簽章、帳本同步、資料等級標記與設定頁的對接。
