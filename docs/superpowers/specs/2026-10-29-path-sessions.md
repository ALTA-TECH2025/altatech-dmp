# 行為路徑：桑基圖數字改成會話數、每會話只取一個起點

- 狀態：規格已確認（Windy 2026-10-29：「去讀神策文檔，試著自己回答」，依神策手冊定案）。
- 起因：controls-2 端到端發現桑基連線的「人數」可以超過起點人數。原本把各條路徑的去重人數直接加總，同一個人走了兩條路徑就算兩次；同一個會話出現兩次起點也會切成兩條路徑。

## 依據（神策分析使用手冊・用戶路徑分析，guide_analytics_path）

原文（簡體）：

> 用户路径分析桑基图中的数字是代表用户数吗？
> 不是的，数字代表 Session 会话数。用户路径分析是基于会话的分析，一个 Session 会话即代表一次完整的访问。

> 值在详细信息中展示的是会话数，并不是用户数，所以会话数和用户列表中的用户数不一定一致。

> 若选择某一事件为起始事件，则会在所有符合条件的会话中，从前往后找到会话中最先发生的该事件，并以此截取后续……

計算口徑範例（手冊）：會話 `E-A-B-A`、`D-F-E`、`A-F-C-F`、`D`；起始事件 A → 只剩 `A-B-A`、`A-F-C-F`；結束事件 F → 只剩 `D-F`、`A-F-C-F`（截到最後一個 F）。

來源：https://manual.sensorsdata.cn/sa/docs/guide_analytics_path/v0300

## 決定

| 項目 | 原本 | 改成 |
|---|---|---|
| 桑基節點／連線的數字 | 各路徑「用戶數」加總（會重複算） | **會話數**（`nodes[].sessions`、`links[].sessions`） |
| 起點（之後） | 會話裡每出現一次起點就切一條 | 每會話只取**第一次**出現 |
| 終點（之前） | 每出現一次終點就切一條 | 每會話只取**最後一次**出現 |
| Top 路徑表 | 人數、占起點用戶比例、會話數 | 人數（去重，給下鑽用戶列表用）、**會話數**、占起點**會話**比例 |
| 摘要 | 起點用戶 | 起點用戶（去重）＋起點會話（新增 `anchor_sessions`） |

每會話只有一條路徑，所以節點、連線把各路徑的會話數加起來不會重複；第 0 層（起點）的會話數 ≤ `anchor_sessions`（差額是被 K 匿名抑制或 Top N 以外的路徑）。

## 不變

- K 匿名：仍以每條路徑的**去重用戶數** < K 抑制（隱私看人，不看會話）。
- 抽樣仍按用戶分桶；跨會話模式（cross）把整段期間當一個會話，等於每人只取第一個起點。

## 相容

- 前端讀 `sessions`，沒有時退回舊欄位 `users`（示範模式的固定資料、舊的看板卡片快取），前後端合併順序不影響畫面。

## 驗收

1. 黃金測試（ClickHouse 對 oracle）：每條路徑的 `sessions` 加總 = 第 0 層節點會話數 ≤ `anchor_sessions`；起點在同一會話出現兩次只算一條。
2. 前端：桑基圖與節點提示顯示「會話」，Top 路徑表的占比改為占起點會話比例。
3. 端到端：任一連線會話數 ≤ 起點會話數（原本被拿掉的斷言補回來）。
