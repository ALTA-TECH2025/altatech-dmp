### D3　模型能看到哪些資料　✅ Windy 已確認（2026-10-21）

**決定：目錄 + 彙總結果。** 模型看得到：

- 事件／指標名稱與說明；
- 每次查詢的彙總表：最多 200 列，已套遮罩與 K 匿名，金額改為區間，不含任何 ID。

用途是比較、下鑽、撰寫結論。**畫面上的數字由 DMP 直接提供**，不經模型產生或轉述，模型的文字不是數值來源。下鑽也遵循同一個可見範圍，不會因此開放明細或 ID。

要分清楚的兩條路：

| | 給模型的「彙總投影」 | DMP 直接給使用者的畫面 |
|---|---|---|
| 內容 | 彙總表（≤ 200 列）、遮罩後、K 匿名、金額區間、無 ID | 依使用者本人權限的完整查詢結果（例如有權限的角色可看金額明文） |
| 來源 | DMP 工具閘道從查詢結果另外產生 | DMP 查詢結果，直接回前端 |
| 用途 | 讓模型決定下一步、寫結論 | 使用者看到的數字、圖表 |

K 值與金額區間分三件事，不可混用：

- **現行安全下限**（已在契約，所有查詢都適用）：`rbac.yaml` `k_anonymity.min_group_size: 20`、`masking.yaml` 的 `bucket` 邊界。模型投影只能比它嚴，不能比它鬆。
- **合成測試設定**：自測與驗收用測試替身模型（`provider: test-double`）時，投影直接套現行下限；只出現在標示為合成的 fixture，不是正式配置。
- **正式模型投影的啟用條件**：模型投影專屬的 K 值與金額區間邊界**尚未核定**（`tools.yaml` `model_view.approved_params: null`）。正式環境要同時有已核定的端點（D2）與投影參數才會呼叫模型；缺任一項，建立 run 時同步回 503 `MODEL_ENDPOINT_NOT_CONFIGURED`（不建立 run），缺的設定放在 `Error.params.missing`；run 進行中才被移除時，工具兜底回 ToolError，缺項放在 `ToolError.detail.missing`。工程不得把現行下限直接填成已核定的投影參數。

**2026-10-28 補：送往模型的還有一條路徑——使用者的問題文字。** 舊稿只列了目錄與彙總結果，但模型實際也會收到使用者在工作台輸入的問題、畫面上下文，以及技能說明（docs/38 §5.2）。使用者可能在問題裡打客戶姓名、身分證或帳號；現有的 `narrative_regex_block` 只管模型輸出、而且還沒有程式使用。問題文字能不能出境、送出前要不要遮掉或拒收，**仍待確認（Q12）**，不視為 D3 已涵蓋。

以下保留當時的選項比較，供日後查考：


| | 模型看得到 | 差異 |
|---|---|---|
| **建議：目錄 + 彙總結果** | 事件／指標名稱與說明；每次查詢的彙總表（最多 200 列，已套遮罩與 K 匿名，金額改成區間，不含任何 ID） | 足夠做比較、下鑽、寫結論；畫面上的數字由 DMP 直接給你，不經模型 |
| 替代 1：只看目錄 | 只看名稱與說明 | 最保守；AI 只能幫你配查詢，不能解讀結果、不能寫結論 |
| 替代 2：含個人明細 | 再加個人時間軸、用戶列表 | 不建議；需要另外的法遵評估 |

不論選哪個：交易、帳務、客戶資料都留在 DMP，不送 GA；啟用 AI 不改變任何資料出境許可。

### D4　AI 可以自己做到哪一步　✅ Windy 已確認（2026-10-21）：中等

**決定：** AI 可以自己查字典、看資料品質、跑彙總分析，建立**私人**看板草稿與受眾草稿（不生效）。分享、發布、排程啟用、受眾送審、匯出、推送／觸達，都由人在畫面上操作；核可仍走數位經營。人工操作也遵循既有 RBAC 與審批流程，**不因 AI 建立了草稿就取得額外權限**。（受眾送審的做法見 2026-10-28 決定 1028-1。）
