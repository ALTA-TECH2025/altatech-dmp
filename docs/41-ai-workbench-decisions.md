> 版本 v0.1 草案（2026-10-20），對應 Issue #34。**狀態：待 Codex 規格複審／待 Windy 確認。** 這一頁只放需要你決定的事，最多 5 項；工程細節已在 docs/38–40 處理，不需要你決定。
> **建立 Issue #34 或這份文件，都不代表你已確認任何一項。** 你回覆前不會開始實作。

## 一句話

建議先做一條可以驗收的路：**開戶漏斗診斷（只讀）→ 開戶主管週報看板草稿 → 「開戶後 7 天未首筆成交」受眾草稿（不送出）**，由 DMP 後端自己控制 AI 的每一步，AI 只看彙總數字、看不到個人資料，所有會生效的動作都還是人按。

## 要你決定的 5 件事

### D1　第一個要做出來的範圍（MVP）

| | 內容 | 差異 |
|---|---|---|
| **建議：修正版切片** | S1 開戶漏斗診斷（只讀）→ 開戶主管週報看板草稿 → S6「開戶後 7 天未首筆成交」受眾草稿（不送審、不推送） | 受眾換成 S6：對象是已開戶、已識別的客戶，名單推得出去；客戶簡報 p15 自己寫了這個場景 |
| 替代 1：原案 | 開戶漏斗診斷 → 看板 → 「開戶流程中斷者」受眾草稿 | 中斷者多半還沒登入（匿名），名單多數推不進 CDP；要做就只能限定「已登入過但沒完成」並顯示覆蓋率 |
| 替代 2：先做通用平台 | 25 個工具、6 個技能全部做完再接場景 | 很久看不到可驗收的結果；容易做成「登記了但不能用」 |

成本主要來自：工具閘道正式化（身分、權限、預算、審計）、run 紀錄與狀態機、前端工作台。三個方案這些都要做；差別在之後要驗收多少場景。

### D2　AI 由誰執行、模型放哪裡

| | 內容 | 差異 |
|---|---|---|
| **建議：DMP 後端自己控制流程，模型用 API 呼叫** | 每一步要查什麼、用誰的權限、花多少預算，都由 DMP 決定並記錄；模型只負責「下一步做什麼、怎麼寫結論」 | 身分、權限、重試不重複寫入都在 DMP 內；換模型供應商不用重做 |
| 替代 1：Claude Agent SDK | Anthropic 提供的 agent 執行框架 | 每個工作要起一個子行程、帶 shell 與檔案能力（要全部關掉）；session 存在本機檔案，跨主機要另外處理 |
| 替代 2：OpenAI Agents SDK／託管 Agents API | OpenAI 提供的框架；託管版由 OpenAI 執行 | 託管版目前只支援美國資料駐留、不支援零資料保留（2026-10-20 官方文件）；應用內 SDK 與建議方案接近 |

建議方案落地、通過驗收後，再用同一組驗收題目接一個替代方案比較（不影響正式路徑）。

**另外要決定的是模型端點放哪**（這是資安／法遵問題，不是工程能定的）：

- 永豐證 GCP 專案內的託管模型端點
- 企業內部 LLM Gateway
- 境外 API

建議：先問永豐資安能接受哪一種，再選供應商。在答案出來前，可以先用規則解析器（不連模型）把工具閘道與驗收做起來。

### D3　模型能看到哪些資料

| | 模型看得到 | 差異 |
|---|---|---|
| **建議：目錄 + 彙總結果** | 事件／指標名稱與說明；每次查詢的彙總表（最多 200 列，已套遮罩與 K 匿名，金額改成區間，不含任何 ID） | 足夠做比較、下鑽、寫結論；畫面上的數字由 DMP 直接給你，不經模型 |
| 替代 1：只看目錄 | 只看名稱與說明 | 最保守；AI 只能幫你配查詢，不能解讀結果、不能寫結論 |
| 替代 2：含個人明細 | 再加個人時間軸、用戶列表 | 不建議；需要另外的法遵評估 |

不論選哪個：交易、帳務、客戶資料都留在 DMP，不送 GA；啟用 AI 不改變任何資料出境許可。

### D4　AI 可以自己做到哪一步

| | AI 自己做 | 需要人 |
|---|---|---|
| **建議：中等** | 查字典、看資料品質、跑彙總分析；建立**私人**看板草稿與受眾草稿（不生效） | 分享、發布、排程啟用、受眾送審、匯出、推送／觸達——都由人在畫面上按；核可仍走數位經營 |
| 替代 1：嚴格 | 只能查與分析 | 連草稿都要你自己建 |
| 替代 2：寬鬆 | 可直接送審或啟用排程 | 不建議；與現有審批制度相衝 |

**附帶一題：** 現行權限下，**行銷角色不能建立看板**（只有檢視權）。如果開戶主管週報要讓行銷用 AI 建，需要給行銷「看板建立」權限，這屬權限治理，請你和永豐確認；否則 MVP 的看板由數據分析或數位經營發起。

### D5　第一批分析的口徑

目前有三個口徑沒有定案，AI 不能自己猜：

| 口徑 | 現況 | 建議 |
|---|---|---|
| 「開戶」指什麼 | 問數解析器把「開戶」當「完成開戶申請」；語意層「新開戶數」當「審核成功」——兩套不一致 | 「開戶」= 審核成功（與語意層、客戶 KPI 一致）；「開戶申請」另外叫申請 |
| S1 開戶漏斗步驟 00→07 | 客戶端「待核定」（簡報 p12、p18B） | 先用提案步驟做、每張結果標「口徑待客戶核定」；客戶核定後重算 |
| S5 文章瀏覽 14 天內開戶 | 需求要匿名綁定覆蓋 14 天；OneID 規則只回填 7 天 | 選一：(a) 回填改 14 天（影響歸戶規則，要走治理流程）；(b) 維持 7 天、分析結果揭露「7 天前的匿名瀏覽未歸戶」。建議 (b) 先做、(a) 另案評估 |

## 已經由現有契約定案、不需要你決定的事

- 身分一律從登入狀態取得；AI 不能自己填使用者或角色。每次查詢、每次排程都重新檢查權限。
- 行級權限、欄位遮罩、K 匿名（20 人）由查詢編譯器套用，與現有分析頁同一套。
- 匯出、推送、分群生效的審批角色（數位經營）沿用現有設定。
- 看板存的是查詢配置（原生看板），不是圖片或 HTML。
- 數字正確性用獨立參考實作比對，不用另一個模型判斷。
- 排程以擁有者「現在」的角色執行，權限失效即暫停（與看板定時寄送相同）。
