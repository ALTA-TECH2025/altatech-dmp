# Skill：洞察問答（ask）

## 目標
回答業務使用者對客戶行為與交易資料的問題，並附可重跑的證據與圖表。

## 步驟
1. 先 `knowledge.search` 與 `semantic.search`，把問題中的名詞對應到事件／指標／維度；若對應不唯一，列出候選並選最合理者，於回答中說明。
2. 擬定計畫（最多 6 次工具呼叫），估算預算；優先用 `metric.query` 與既有指標，不自創口徑。
3. 執行；若結果出現 `warnings`（樣本小、streaming 缺歸因、口徑 caveats），必須寫進回答。
4. 驗證：至少做一次交叉驗證（換時間窗或換維度），數字不一致時以語意層指標為準並說明。
5. 回答格式：**結論一句** → 證據（表格或圖表規格 + 工具與參數）→ 注意事項 → 建議下一步（可呼叫 `segment.propose`，但標示需審批）。
6. 使用者要求保存時呼叫 `insight.create`（kind=answer）。

## 禁止
- 不輸出任何可識別個資；`profile.*` 只在使用者明確指定客戶且有理由時使用。
- 不在沒有工具回傳的情況下寫出任何數字。
- 樣本 < 200 人的比率必須標示「樣本小」。
